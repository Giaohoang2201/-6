# 과제 06: 순차 탐색, BST, AVL 트리의 성능 비교

## 1. 실행 방법

```
gcc -Wall -O2 -o assignment06 assignment06.c
./assignment06 20260605      # 인자는 난수 시드 (생략하면 time(NULL))
```

- 아래 분석은 시드 `20260605`의 실행 결과(`result.txt`)를 기준으로 합니다.
- **숫자 비교 1회**: 새 값(또는 탐색 키)과 저장된 값 하나를 비교하는 연산 1회입니다. 같다/작다/크다 판정은 1회로 셉니다. AVL의 높이 계산, balance factor 확인, 회전 판단은 세지 않았습니다.
- 높이는 노드 수 기준(빈 트리 0, 루트만 1)입니다. AVL 높이는 저장된 `height` 필드와 별개로 트리를 재귀 순회해 다시 계산해 일치함을 확인했습니다.
- 탐색 때마다 세 방법의 성공/실패 결과가 일치하는지 검사합니다.

## 2. 실험 결과

### 생성 단계

| 항목 | 값 |
|---|---|
| 생성한 난수 | 100개 |
| 실제 저장된 서로 다른 값 | **93개** |
| 중복으로 삽입하지 않은 값 | 7개 |

| 자료구조 | 생성 중 비교 횟수 | 크기/높이 |
|---|---|---|
| 배열 | 4,491 | 길이 93 |
| BST | 614 | 높이 13 |
| AVL | 527 | 높이 8 |

### 탐색 단계 (탐색 키 50개, 이 중 성공 2개 / 실패 48개)

| 방법 | 총 비교 횟수 | 평균 비교 횟수 |
|---|---|---|
| 순차 탐색 | 4,621 | 92.42 |
| BST 탐색 | 433 | 8.66 |
| AVL 탐색 | 338 | 6.76 |

## 3. 분석

### 3.1 BST와 AVL의 높이가 다른 이유

두 트리에는 같은 93개 값이 같은 순서로 들어갔으므로 BST도 AVL도 중위 순회하면 똑같이 정렬된 값이 나옵니다. 다른 점은 **모양**뿐입니다.

- 일반 BST는 삽입 순서가 만든 모양을 그대로 유지합니다. 이번 입력에서는 삽입 순서 때문에 일부 가지가 깊게 이어져 높이가 13이 되었습니다.
- AVL은 삽입할 때마다 두 서브트리의 높이 차이가 1을 넘으면 LL/RR/LR/RL 회전으로 바로잡습니다. 그래서 한쪽으로 길게 늘어난 가지가 만들어지지 않고 높이가 8에 머물렀습니다.
- 노드가 93개이면 높이는 최소 7(2^7−1 = 127 ≥ 93 > 63)이므로, AVL(8)은 이론상 최적보다 1만 큰 거의 완전한 균형입니다. BST(13)는 최적보다 6이나 깊습니다. 무작위 입력이라 BST가 최악(높이 93)까지 가지는 않았지만, 균형이 보장되지 않아 입력에 따라 편차가 큽니다.

### 3.2 높이가 탐색 비교 횟수에 미치는 영향

트리 탐색은 루트에서 한 레벨 내려갈 때마다 비교를 1회 하므로, 탐색 비용은 **방문한 경로의 길이**, 즉 최대 트리 높이에 비례합니다.

- 높이 13인 BST에서 탐색 한 번당 비교 횟수는 5~13회로 넓게 퍼졌고(13회가 6건), 평균은 8.66회였습니다.
- 높이 8인 AVL에서는 5~8회에 모두 들어왔고(7회가 36건) 평균이 6.76회였습니다. BST보다 총 비교가 433 → 338회로 약 22% 적습니다.
- 탐색 키 50개 중 48개가 실패(해당 값이 없음)였기 때문에 대부분 말단 근처까지 내려가는 탐색이었습니다. 이 경우 비교 횟수가 거의 "해당 경로의 깊이"와 같아서 높이 차이가 그대로 드러났습니다. 성공 탐색이 많았다면 얕은 노드에서 멈추는 경우가 늘어 BST와 AVL의 차이가 조금 줄었을 것입니다.
- AVL의 평균(6.76)은 높이(8)보다 낮은 반면, BST의 평균(8.66)은 높이(13)에 비해 크게 낮습니다. 즉 BST는 깊은 가지가 일부에 몰려 있어서 대부분의 탐색은 높이보다 훨씬 얕게 끝났다는 뜻입니다. 그래도 최악 경로는 BST가 훨씬 길어서, 최악 경우를 기준으로 하면 격차가 더 큽니다.

### 3.3 배열 순차 탐색과 트리의 비교

- 순차 탐색 실패는 항상 배열 길이 93회 전부를 비교합니다. 이번 실험에서 평균이 92.42회로 길이 93에 거의 붙어 있는 이유입니다(성공 2건만 이보다 적음). 비용이 O(n)이어서 데이터가 많아질수록 선형으로 늘어납니다.
- 트리는 O(높이)입니다. AVL은 O(log n)을 보장하고 BST는 입력에 따라 O(log n)~O(n)입니다. 이번 실험에서 순차 탐색은 BST의 약 10.7배, AVL의 약 13.7배 비교를 했습니다.

### 3.4 생성 비용과 탐색 비용

| | 생성 비용 | 탐색 비용 |
|---|---|---|
| 배열 | 4,491 (가장 큼) | 평균 92.42 (가장 큼) |
| BST | 614 | 평균 8.66 |
| AVL | 527 (가장 작음) | 평균 6.76 (가장 작음) |

- **배열의 생성 비용이 큰 이유**: 새 값을 넣을 때마다 중복 확인을 위해 지금까지 저장된 원소를 처음부터 끝까지 봐야 합니다. i번째 삽입은 최대 i−1회를 비교하므로 전체가 약 n²/2에 비례합니다(93개 기준 약 4,300회 + 중복 확인 비용). 정렬된 구조가 아니라서 비교를 줄일 방법이 없습니다.
- **트리의 생성 비용이 작은 이유**: 삽입마다 루트에서 삽입 위치까지만 내려가므로 비용이 각 삽입 시점의 트리 깊이에 비례합니다.
- **AVL이 BST보다 생성 비교도 적은 점**: 회전이 비교 횟수 자체를 늘리지는 않지만(회전은 세지 않음), 균형을 유지하면 이후 삽입들이 더 얕은 경로를 따라가기 때문에 누적 비교가 줄었습니다(614 → 527). 다만 AVL은 삽입마다 높이 갱신과 회전이라는 **비교 횟수에 잡히지 않는 추가 작업**을 합니다. 과제 정의상 이 비용은 제외했지만 실제 실행 시간에서는 AVL의 삽입이 항상 유리하다고 볼 수는 없습니다.
- **결론**: 한 번 만들고 탐색을 많이 하는 상황이면 AVL이 가장 유리하고, 균형 유지 비용이 필요 없는 짧은 데이터나 한두 번의 탐색이면 단순한 구조가 낫습니다. 이번 실험(삽입 100회, 탐색 50회)에서는 두 비용 모두 AVL이 가장 적었고, 순차 탐색 배열이 가장 불리했습니다.

## 4. 한계

- 시드 하나의 결과이므로 BST의 높이(13)는 이 입력의 우연이 섞여 있습니다. 다른 시드로 실행하면 BST 높이와 비교 횟수는 달라집니다. 그래도 AVL이 BST보다 낮거나 같은 높이를 갖는 경향은 유지됩니다.
- 탐색 키 50개 중 성공이 2개뿐인 것은 값의 범위(0~1,000)에 비해 저장된 값이 93개로 적기 때문입니다. 성공 탐색 위주로 실험하려면 탐색 키를 저장된 값에서 고르는 별도 실험이 필요합니다.
